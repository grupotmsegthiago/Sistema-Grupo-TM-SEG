Como implementar essa trava em todas as telas
Para que o sistema respeite essa regra de "uma vez salvo, não altera mais", você deve aplicar uma lógica de ReadOnly (Somente Leitura) baseada no status de aprovação.

1. Lógica no Frontend (Replit)
Você deve desabilitar todos os inputs e botões de ação se houver um registro de salvamento ou aprovação:

JavaScript
// Exemplo de verificação de trava
const isLocked = osData.status_faturamento === 'APROVADO' || osData.ultimo_salvamento != null;

// No seu código, aplique a propriedade 'disabled' nos componentes:
<button disabled={isLocked} onClick={handleSave}>SALVAR AJUSTES</button>
<button disabled={isLocked} onClick={handleEdit}>EDITAR</button>
<input disabled={isLocked} value={kmReal} />
2. Proteção no Banco de Dados (Supabase)
Para garantir que ninguém altere os dados diretamente via API ou console, você pode criar uma Trigger no banco de dados que impede o UPDATE se a coluna status_faturamento for 'APROVADO'.

SQL
CREATE OR REPLACE FUNCTION proteger_os_aprovada()
RETURNS TRIGGER AS $$
BEGIN
    IF (OLD.status_faturamento = 'APROVADO') THEN
        RAISE EXCEPTION 'Esta OS já foi aprovada e não pode ser alterada.';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_bloqueio_os_aprovada
BEFORE UPDATE ON ordens_servico
FOR EACH ROW EXECUTE FUNCTION proteger_os_aprovada();

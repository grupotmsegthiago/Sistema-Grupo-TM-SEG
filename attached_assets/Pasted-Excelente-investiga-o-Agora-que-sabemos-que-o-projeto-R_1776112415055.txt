2. Implementação do Código (Para o financialUtils.ts)
Podes usar este trecho como base para substituir ou ajustar a regra por volta da linha 614:

// Definição de Tipos (TypeScript)
interface FinancialResult {
  client_price_table_id: number;
  toll_client: number;
  toll_supplier: number;
  // ... outros campos
}

/**
 * DOCUMENTAÇÃO:
 * Ajuste da Regra Soberana para CEVA LOGISTICS - Operação Jundiaí 200KM.
 * Local: lib/financialUtils.ts
 */
export const applyCevaSpecialRule = (
  missionData: any, 
  currentResult: FinancialResult
): FinancialResult => {
  
  // 1. Verificação das condições exatas
  const isCeva = missionData.client_name?.includes("CEVA LOGISTICS");
  const isJundiai = missionData.origin_city?.toUpperCase().includes("JUNDIAI");
  const is200km = missionData.selected_option === "200KM";

  if (isCeva && isJundiai && is200km) {
    return {
      ...currentResult,
      // Forçamos o pedágio para R$ 35,00 (substituindo os R$ 38,00 antigos)
      toll_client: 35.00,
      toll_supplier: 35.00,
      
      // A lógica de scoring deve ser ignorada aqui para garantir 
      // que a tabela "SUDESTE - OPERAÇÃO LOGITECH - 200KM" seja a escolhida
      // Se você tiver o ID exato, pode fixar aqui:
      // client_price_table_id: 123 
    };
  }

  return currentResult;
};
3. Instruções para implementar no Replit
Como não estamos a usar document.getElementById, deves seguir estes passos dentro do código React:

Ajuste de Valor: No lib/financialUtils.ts, procura onde está definido o valor fixo de 38.00 e altera para 35.00.

Sincronização de Estado: No componente React que renderiza essa tela (provavelmente algo como MissionForm.tsx ou BillingAudit.tsx), garante que o useEffect que dispara o cálculo esteja a observar as mudanças nos campos de Origem e Franquia.

Exemplo: useEffect(() => { calculate(); }, [client, origin, kmOption]);

O "Bug" do Recalcular: Se o sistema ainda pede para "Recalcular", é porque o estado local do formulário (useState) não está a ser atualizado com o retorno da função calculateMissionFinancials. Garante que o resultado da função de utilidade esteja a fazer um setFormData ou similar.
